# 高位下拉起拉后摆反馈

FitPal 在固定侧面机位测量起拉早段的肩髋投影角变化。一组内反复出现明显后摆时，组后给出被标记的动作编号和调整建议。逐次回顾显示发生的时刻和投影角变化。下一组有足够可比的动作时，显示两组的后摆次数与各自可评估的分母。幅度跟个人校准比较，持续可见的起拉变化单独评估。

- 可评估条件包含可见的同侧肩髋、侧面轮廓，以及手臂和躯干稳定的起点。检测包含肘角状态机确认下拉前的帧。取景中断、视角不稳定或关键点缺失时须重新取得稳定起点。当前后摆门槛是相对稳定起点向后增加至少 15° 并持续至少 100 毫秒，属于初版实验规则。
- 组后提醒至少要有两次可确认的后摆。持续的取景问题优先。每组至少两下可评，且大部分已计数的动作可评估，才比较前后比例。比较还会检查朝向、画面中躯干的尺寸、同侧髋的位置，以及本组下拉幅度是否明显下降。
- 结果描述画面可见的运动。此阶段可观察到起拉模式的变化，还没有做真人收到提示后再练习的对照研究。

## 真人录像验收

借用了此前收集的 [Castle Hill Fitness 同一教练示范](https://www.castlehillfitness.com/fitness-training/exercise-tip-lat-pull-down)。先查看原始 RGB，选出示范片 1.70–5.55 秒的稳定侧面周期，以及错误演示 0.95–3.23 秒的明显后摆周期。两段均为同一人和同一机位，保留原动作速度，剪接点位于两次动作之间。为了测试两组交互，先将稳定周期重复三次作为校准，接两次后摆作为第一组，再将稳定周期重复三次作为第二组。使用 Chromium 走真实的 FitPal 训练路由，测试工具把本地录像作为模拟摄像头输入。

| 回放 | 实际界面 |
|---|---|
| 第 1 组 | 2 下均达个人幅度，逐次回顾同时标记后摆。组后点名第 1、2 下并提示保持上身稳定。 |
| 第 2 组 | 3 下可评，起拉均未检测到明显后摆。复查显示上组 2/2、本组 0/3。 |
| 初版漏报 | 同一段第 1 组曾把两下都标作后摆未评估。起拉偏差已发生时，较晚的肘部状态才触发动作记录。冻结早于动作触发的稳定躯干窗口后复跑通过。 |
| 另一次实时回放 | 同样的第一组录像有一次只确认 1 下，逐次结果标记了这一下后摆，但组后没有触发重复偏差的提醒，也无法形成两组复查。 |
| 取景变化 | 追加重复后摆，让第一组有 3 下可评。第二组仍评为 0/3 后摆，将画面水平移 74 像素后，复查显示「两组的取景、可用动作或下拉幅度不足以直接比较」。 |

素材由单人筛选，重复拼接用于验证交互路径。它仍是同一个训练者、两个原始动作周期。两组显示的变化来自两段已录制的动作，无法衡量用户是否因提示而改善。原始第三方素材通过来源页观看。

演示在校准和正式第 1 下之间加了字幕。该次录屏中，模拟摄像头输入在 16.90 秒切入后摆片段，FitPal 在 17.95 秒进入正式第 1 下的下拉阶段，在 19.32 秒确认这一下。该组的逐次回顾显示下拉阶段确认后 0.27 秒，躯干的侧面投影相对起点向后偏转约 46°。录屏的复查显示上组 3/3、本组 0/3。

实时骨架和轨迹的显示坐标经过平滑处理。姿势判断、角度、计数及断轨仍基于原始关键点。对以上两个原始动作周期逐帧复测后，满足骨架可见条件的左膝和左踝每帧位移中位数分别从 1.4 降到 0.0 px（稳定示范），从 3.5 降到 1.9 px（后摆示范），以 638 × 640 的原片尺寸计算。

起拉反馈初版用七段正常、短幅、遮挡和手腕出画案例做了浏览器回归，七段组后反馈与预期一致。骨架平滑版本通过 128 项前端测试、6 项 Python 测试和生产构建，并回放了新版演示的两组动作。
