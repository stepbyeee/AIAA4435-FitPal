# 高位下拉双臂遮挡回放

高位下拉的摄像头、文件回放和内置示范共用一套双臂轨迹。摄像头固定、双臂张开时，程序从连续至少 350 毫秒的观测学习两个握持位置。模型暂时交换左右标签时，程序按实际位置重新关联肩、肘和腕。某侧缺少可信关节，或整段骨骼落在几乎没有图像细节的区域时，该侧清空轨迹。下一次重新看到这只手，轨迹从当前位置开始。肘或腕单独出画时，仍保留可见关节供计数器使用。

## 为什么仅靠关节置信度会出错

在 GO4IT 背面片段 17 秒起遮住左臂，Full 有时会把左腕估计到身体中间。在一次诊断回放的 17.3 秒附近，无遮挡画面的左腕约为归一化坐标 (0.29, 0.08)，遮挡后的估计为 (0.57, 0.65)，置信度仍达 0.85。原来的 0.60 置信度门槛允许画出这条线。约 19 秒时，模型还会把仍可见的右臂标成左臂。两种错误会同时导致遮挡侧有线、可见侧断线。

## 固定帧结果

同一份 GO4IT 背面节选，以 15 Hz 送入 CPU 版 Full。每种条件单独初始化模型，原版和新版共享该条件的同一批模型输出和轨迹绘制函数。在第 17–22 秒和 27–32 秒各遮住一侧。统计每段中间 4.2 秒，各 63 帧。墙纹来自原画面静态背景，也交换了遮挡先后侧别。这两种组合都属于同一个人的人工遮挡实验。[逐窗口结果](results/pulldown-arm-occlusion-v2.json)

| 条件 | 遮挡侧误画，改前 → 改后 | 可见侧有轨迹，改前 → 改后 | 可见腕位置接近无遮挡参考，改前 → 改后 |
| --- | ---: | ---: | ---: |
| 灰色遮挡，先左后右 | 64 → 0 / 126 帧 | 50 → 82 / 126 帧 | 28 → 44 / 123 帧 |
| 墙纹遮挡，先右后左 | 12 → 0 / 126 帧 | 95 → 87 / 126 帧 | 76 → 76 / 123 帧 |

最后一列要求可见腕与无遮挡回放的同侧腕距离不超过画面高度的 10%。只纳入原图两腕都能定位且充分分开的 123 帧，参考位置由 Full 给出。灰块左侧遮挡的窗口依然很难。新版有 30/63 帧能画出右臂，只有 5/63 帧的腕位置接近参考。画出轨迹本身不能说明定位正确。

四次遮挡均从第一帧起断开。移开遮挡后，恢复至连续两帧可绘制的时间为 0.13–0.53 秒。无遮挡对照的 141 个非边界帧中，原版左右臂各显示 141 帧，新版分别显示 140 和 139 帧。滤镜每帧耗时的第 95 百分位在各条件下为 0.2–1.2 毫秒，仅包含筛选和像素读取。窄握、侧拍、人与器械长时间重叠仍可能让两侧关联失败。

## 新视频中的自然遮挡

Pexels 35585697 是竖屏正前方偏侧的下拉录像。相机横移时，一根器械立柱挡在训练者左臂前面。先仅看原片，选取 12 个短窗口，逐帧对每侧肩、肘、腕是否可见做判断并锁定标签，再与两版轨迹对照。36 帧共 72 个侧别观测，9 个边界不明确的观测排除。立柱遮挡和腕部也可能同时出画。[原片来源](results/pulldown-r2-unseen-stock-sources.json) · [人工标签](results/pulldown-arm-natural-reference.json) · [按窗口计数](results/pulldown-arm-natural-audit.json)

| 单侧人工标签 | 侧帧数 | 旧版画出 | 新版画出 |
| --- | ---: | ---: | ---: |
| 器械立柱遮挡 | 6 | 4 | 0 |
| 有关节出画 | 18 | 2 | 2 |
| 肩、肘、腕可见 | 39 | 35 | 29 |

这段实录中，立柱后的错误连线减少，清楚可见的手臂也多断了 6 个侧帧。样本来自同一位训练者，连续的三个相邻帧构成一窗，由一人标注。表中度量是每侧是否画出，位置误差需要额外的二维关键点人工标注。

## 复跑

在 `ui/` 启动 Vite。将本机 Chrome 可执行文件路径设为 `FITPAL_CHROME`，把 `FITPAL_URL` 设为本地开发服务地址。下面各项分别跑固定帧对照、真实页面采样和以相同视频作为虚拟摄像头输入的采样。最后一项用计数实验导出的逐帧轨迹复核人工标签。

```sh
node scripts/compare-arm-occlusion.mjs --output /tmp/arms-fixed.json --movie /tmp/arms-comparison.mp4
node scripts/check-unilateral.mjs --output /tmp/arms-ui.json
node scripts/check-unilateral.mjs --camera --output /tmp/arms-camera.json
python3 scripts/score-arm-visibility.py --reference ../docs/results/pulldown-arm-natural-reference.json --trace /tmp/traces/pexels-35585697.mp4.json --output /tmp/arms-natural.json
```

实际页面每秒采样五次，灰块挡住左、右臂的两个窗口，各有 21 个采样点。左、右误画均由 8/21 降至 0/21，可见的另一侧分别从 6/21 增至 11/21、从 11/21 增至 18/21。[旧版页面](results/unilateral-obstruction.json) · [新版页面](results/pulldown-arm-occlusion-ui-v2.json)。使用 Chromium 的文件虚拟摄像头经过 getUserMedia 再测，左侧遮挡误画 1/21，右侧 0/21，可见另一侧分别画出 7/21 和 17/21。这个测试经过实时摄像头入口，真实健身房硬件的延迟和光照仍需现场测量。[虚拟摄像头结果](results/pulldown-arm-occlusion-camera-v2.json)。视频原作者为 Health TV，本次增添遮挡、轨迹和状态文字。[源素材与许可](../ui/public/showcase/CREDITS.txt)
