# FitPal 高位下拉回放与课程验证

For the expanded two-exercise evaluation, model comparisons and classroom workflow, see the [current validation report](validation.md). The results below describe the original two-video replay.


## 已实现的训练流程

1. 浏览器本地运行 MediaPipe Pose Landmarker Full。骨架和动作判断共用同一份带时间戳的关键点。
2. 用户在固定机位做三次清晰的完整下拉。系统比较两侧关键点的可用性，选一侧手臂，以肩、肘、腕的二维投影角估计个人活动范围。计数还检查手腕是否回到本次动作的起始高度附近。保持同一机位和握法能让后续幅度可比较。
3. 清晰但幅度偏短的完整动作仍计一次，并留下短幅度记录。动作中的遮挡会让该次失去验证资格。组中实时显示骨架和计数，组后最多给一条改进提示。现有角色在有幅度提示时演示目标动作。结算详情显示逐次幅度、画面可用率和结束触发。
4. 录像到末尾只结算一次，回放成绩不进训练历史。正常训练结束一组后释放摄像头。EXP 和组摘要保存在本地。语言提示当前是确定性规则文案。

标准示范的右臂关键点通过了全部已处理帧的可用性检查，左臂因侧面自遮挡通过率为 0%。校准成功约在 10.52 秒。两次验证动作与人工标注的一对一匹配结果为 2 TP、0 FP、0 FN。匹配窗口是可见最低点到人工标注近完全伸展后 0.25 秒。系统在回程达到阈值即确认，两个计数分别早于手工标注的近完全伸展约 0.70 秒和 0.47 秒。错误示范末段匹配时间为 10.845 秒，前三个剪辑片段均未计为完整动作。

表中 latency 是浏览器对已采样帧的 `detectForVideo` 与关键点映射用时。暂停首帧预热在播放前执行，含设置与预热的时间分别约为 390 ms 和 347 ms。课程提案里的 ≤200 ms 指结果延迟，摄像头采集、界面渲染和动作时机偏差仍需另测。可用率的分母是已处理帧，采样率单独报告。两段都用于调试，后两次动作只是同一片段中未参与个人校准的动作。这里无法估计新用户、陌生机位或设备上的准确率。错误示范也无法单独验证幅度提示的准确性。

## 复现

在 `ui/` 按 [运行说明](../ui/README.md) 安装依赖与模型，准备两段原片并启动本地服务器。已安装 Playwright 及 Chromium 的环境可运行以下命令。也可用 `FITPAL_PLAYWRIGHT` 指向本机 Playwright 模块。

```bash
node scripts/replay-pulldown.mjs --check > replay-summary.json
```

脚本会输出人工标注、计数匹配、按镜头分段的覆盖率和耗时。使用 `--trace /tmp/fitpal-replay-trace.json` 可额外保存测试视频的手臂关键点。默认回放与正常训练不会保存逐帧关键点。

## 浏览器回归

- 生产构建和 35 项单元测试通过。
- 实际 UI 回放验证了标准示范的 2 次结算、剪辑示范的校准不足提示、录像文件缺失和无摄像头预览。回放与预览均未写入训练记录。
- 生产构建用录像模拟摄像头走完三组。第一组顶端停留 5 秒自动结束，后两组手动结束。三组分别验证 2、1、1 次动作，每组结束均停止视频轨，刷新后仍有一条完整训练记录。测试期间页面未发出站外请求。真实健身房摄像头测试仍待进行。

## 课程后续验证计划

1. **固定技术验收协议。** 收集多位参与者及相机角度的独立短片，包含可见短幅度、手腕出框、器械遮挡和中途停顿。按参与者分开调参与验收数据。人工记录完整动作、最低点、遮挡与是否可验证，报告计次 precision / recall、有效覆盖、端到端延迟和每类失败。
2. **验证反馈条件。** 沿用中期 proposal 的文字与关节目标卡、逐次与组后两项比较。对照条件保持感知、负载和提示内容一致，随机平衡顺序。提前确定打断感、任务负荷、动作目标匹配与动机的测量方式。待对照条件与正式 rubric 确认后，再按 proposal 组织 8–12 人探索性测试。
3. **完成整合与交付。** 确定是否在规则输出之上接入仅解释结构化提示的 LLM，核查语义一致性，再按 rubric 整理 demo、录像证据、局限和用户研究。Canvas 正式评分表尚未核验。
