# FitPal 验收记录

本版以高位下拉为课程任务，深蹲为第二个个人校准动作。项目首页还有「坐姿划船 · 侧面计数」实验入口和肩上推举手动记录。三段内置示范可以在准备好模型后离线播放。只有正式摄像头训练才会保存已确认次数和 EXP。摄像头画面、本地导入的视频和逐次轨迹都留在当前设备。[运行说明](../ui/README.md) · [内置示范署名](../ui/public/showcase/CREDITS.txt)

## 课堂展示怎么走

1. 在首页选「录像回放 → 高位下拉示范」，打开「画中分析」。看后视训练者先做三次校准，再看正式次数。两种颜色对应两只手，角度曲线用同样的颜色。
2. 在组后点选不同的动作。幅度是相对于此人、此机位三次校准的百分比。图上标出最低关节角、动作计时和可用轨迹。回顾不把中断的部分连线。深蹲用髋膝踝、膝角和髋相对脚踝的轨迹。
3. 打开「课堂试测」体验逐次或组后反馈、文字或关节目标卡。主持人可以按匿名编号分配四轮、下载量表和汇总评分。EXP 显示与隐藏在参与者间分配。试测结束后，所有零提示、退出和未完成轮次均应记录。[主持手册](pilot.md)

高位下拉在两轮修改后另做了独立盲测。历史调试片达到 11/12，最后四位未参与调试的训练者为 2/8。[高位下拉专项报告与逐片对照](pulldown-before-after.md)

## 哪些结论有测试依据

| 问题 | 所见结果 |
|---|---|
| 在真实录像上该用哪个姿态模型？ | 在同一输入、计数器和匹配规则下，主矩阵 Full 匹配校准后 11/14 个参考动作，Lite 9/14，Heavy 7/14。额外两人的深蹲片段中 Full 匹配 6/10。随后找到的独立 Mixkit 下拉片段有六次动作，最高点手腕出框，Full 未完成校准，三个应计训练动作全漏。主矩阵和补测中 Full 的正式计数均无多计。样本量和机位会明显影响结果。[逐片结果、帧率、权重与来源](model-comparison.md) |
| 换模型架构呢？ | MoveNet Lightning 在四个预选时间窗、现有可见度门槛下匹配 0/11 个正式动作；将 MoveNet 的分数门槛放宽后匹配 2/11。未来采用该模型需另行验证其置信度和计数策略。[权重和阈值敏感性](movenet-benchmark.md) |
| 新增的坐姿划船支持到什么程度？ | 独立的侧拍实验计数器在四个不同训练者录像上分别匹配 1/1、7/8、2/5、0/4 个回程，共 10/18。最后一条在规则冻结后取得，腕部多次出画。划船采用水平伸臂与回程规则，和下拉、深蹲的三次校准协议不同。该入口支持摄像头与文件，保留手动记录通道。[划船实验与误判复测](seated-row.md) |
| 视觉幅度判断能识别什么？ | 在一条已有真人录像中人工缩短一个动作，界面报 80% 和 100%，只对第一下给幅度提示。另测水平镜像、降低分辨率、1.5 倍速和停在顶端；五种改动各重复两遍，10/10 符合预期。人工修改产生的标签只能验证这些特定情形。[控制实验](results/pulldown-controlled-stress.json) |
| 双臂会正确断线吗？ | 高位下拉现在自动分别追踪两臂。对同一背面实录加灰块和墙纹，各遮左、右臂五秒。被遮侧误画从 64/126 帧、12/126 帧分别降到 0。墙纹条件下另一侧有线的帧也从 95 降到 87。真实机位还要看器械和双臂是否重叠。[逐侧遮挡实验](pulldown-arm-occlusion.md) |
| 能跟住画面里的哪一个人？ | 在左静止、右运动的合成双人场景，选左侧无计数，选右侧完成 3 次校准和 2 次计数。在真实教练入镜镜头中，裁左或中间均未完成校准。默认完整画面；该取景能力没有验证为稳定的身份追踪。[受控双人](results/focus-controlled.json) · [自然双人](results/focus-coach.json) |
| 连续训练会释放摄像头吗？ | 在同一个无头 Chrome 标签页、通过模拟摄像头输入实际动作录像，连续完成 24 次会话、每次 3 组。每组结束都检查媒体轨道关闭、历史逐次累计，并核对总计 72 次关闭。[逐次运行记录](results/camera-soak.json) |
| 训练奖励能走完整个流程吗？ | 用真人下拉录像循环输入模拟摄像头，三组各确认十次且均达幅度目标。实际页面发放 45 EXP，升到 Lv 2，购买发带后刷新仍保留。关闭保存后再练三组没有新增历史、EXP 或收藏券。30 个计数均能对齐重复录像中的相应回程。开发服务器的一轮测试中断在第二组，冻结发布包的完整复跑通过。[逐组合成摄像头记录](results/reward-flow.json) |
| 生成提示有依据吗？ | 可选的本地 Qwen2.5-0.5B 只能从本组有效观察和允许的下一步中组成一条提示。四种有问题的输入均生成可接受提示，正常组没有发起推理。真实视频叠加 0.6 秒全遮挡后，其中一次无法确认、另一次确认，界面给出一次可见性提示。课堂条件的措辞固定。[模型配置与测试](local-coach.md) |
| 能自建测试集吗？ | 本地标注页记录起点、最低点、返回点、幅度偏短和遮挡。导出可直接交给相同的评测脚本。校验视频 SHA-256；两人独立导出的标注可以比较计数、漏标、范围分歧和时间偏移。已走通真实视频的标注及评分流程；一致性工具用合成差异验收。[数据集与标注指南](local-video-labeling.md) |

正式计数的分母只含原片中按协议应进入训练的完整动作。短片、动作截断或无法提供可靠参考的录像仍保留在素材清单及覆盖率测试中。前述三种 MediaPipe 预训练权重在 22 个源视频的 24 个时间窗共做 72 次回放，18,018 帧次推理。这一组统计独立于 MoveNet、实验划船及其他小样本补测。

## 浏览器与离线课堂包

从干净目录使用锁定依赖安装，首次下载官方 Full 权重后核对 SHA-256，运行测试和生产构建。发布包只包含运行时、字体、角色资源与三条已署名的示范。17 个 Chromium 工作流覆盖手机画中分析、文件导入、左右侧设置、匿名课堂评分、摄像头拒绝与释放、历史、资料清除等。[浏览器逐项验收](results/session-check/session-checks.json)

测试断网时发现视觉 SDK 会尝试访问 Google 的日志端点。页面使用浏览器的连接策略限制依赖可访问的地址，训练和示范在本机完成；可选语言模型连接本机 5191 端口。从离线包播放高位下拉和深蹲时，Chromium、Playwright WebKit、Firefox 均确认 4 次下拉和 2 次深蹲。每个用例都观察到浏览器自身拦截日志端点，外站网络请求为零，个人历史没有变化。[策略生效前](results/offline-class-demo-before-policy.json) · [三种浏览器的最终记录](results/offline-class-demo-final.json)

## 提案验收还缺什么

- **精确率、召回率与可见率。** 样本中 Full 的匹配计数没有多计，但主矩阵召回为 78.6%，补充深蹲为 60%。多人入镜时可用关节可能来自另一人，无法用几何可见率替代身份正确性。暂未证实不同机位下召回和覆盖均达 90%。
- **延迟。** Apple M5、Chrome 的同帧 CPU 对照中，Full 各片暖态单帧推理 P95 的中位数为 33.7 毫秒。浏览器测试另记回调开始到下次动画帧的耗时。两者都缺少真实摄像头曝光到屏幕反馈的端到端测量。
- **幅度与用户体验。** 带自然短幅动作、双人独立标注的真人录像仍不足。程序测试覆盖了试测配置、触发和问卷导出，尚未组织提案中的 8–12 人用户研究，也没有现场验证真实健身房摄像头。未能取得教师正式评分细则，本记录按仓库的中期提案核对。
